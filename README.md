# Лабораторная работа № 2. Мониторинг процессов в Linux

Цель работы — проверить, сколько короткоживущих процессов успевает заметить утилита ps, и сравнить результат с подсчётом событий ядра через bpftrace.

## Ход работы

1. Посмотрел доступные точки трассировки. Для опыта выбрал sched_process_fork. Список найденных точек сохранил в tracepoints.txt.
2. Написал скрипт load.sh, который последовательно запускает 200 процессов sleep. Каждый из них ждёт около 20 мс.
3. Написал скрипт poll.sh. В течение 10 секунд он вызывает ps с паузой 0,1 секунды, отбрасывает строки с командами в квадратных скобках и считает уникальные PID.
4. Одновременно с опросом запустил bpftrace. Функция count() считает события создания дочерних процессов генератора. Команда запуска находится в run.sh.

## Результаты

| Показатель | Количество |
|---|---:|
| Всего уникальных PID увидел ps после фильтрации | 254 |
| Тестовых процессов увидел ps | 25 |
| Тестовых процессов зарегистрировал bpftrace | 200 |
| Тестовых процессов пропустил ps | 175 |

## Вывод

Из 200 тестовых процессов утилита ps заметила 25 и пропустила 87,5%. Процесс sleep жил около 20 мс и мог успеть запуститься и завершиться между двумя вызовами ps. Через bpftrace удалось посчитать такие процессы, потому что счётчик срабатывал в ядре в момент создания дочерней задачи.

Результат сохраняется в result.txt.
